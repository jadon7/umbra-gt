# UMBRA GT · 街头赛车游戏

画面对标《极品飞车：不羁》的 3D 赛车游戏，分 8 个阶段开发。当前完成**阶段 1：赛车与展厅**、**阶段 2：驾驶手感与镜头**、**阶段 3：城市与赛道**、**阶段 4：光照与后期**、**阶段 5：天气与地面**、**阶段 6：特效**、**阶段 7：玩法、UI、音频**。

在线试玩：<https://umbra.dsxzai.com/>。宣传片（2560×1440、60 帧）在仓库的 Releases 里。

**授权**：代码用 MIT 授权（见 `LICENSE`）。主角车模型基于 Eric Chadwick 的 Car Concept（© 2024 Darmstadt Graphics Group GmbH，CC BY 4.0）修改而来，不在 MIT 范围内，使用时要按 CC BY 4.0 署名（详见文末「主角车模型」一节）。

## 运行

```bash
npm install
```

```bash
npm run dev
```

浏览器打开 `http://localhost:5173`，进入主菜单。需要支持 WebGPU 的浏览器（新版 Chrome、Edge、Safari）。手机上也能玩，见下面「在手机上玩」。

主菜单有五项：

- **开始比赛**：选赛道、圈数、对手数量、难度、时段和天气，和 AI 对手跑一场
- **自由驾驶**：一个人随便开，可以随时切换时段和天气
- **赛道**：点一下在两条赛道之间换——城里的「霓虹湾环线」和山里的「云岭山道」。比赛和自由驾驶都在选中的这一条上；第一次进某条赛道要等几秒钟生成，之后换来换去不用再等
- **车库**：换车漆、副色、尾翼、轮毂、卡钳（原来的展厅）
- **设置**：音量、画质（高 / 中 / 低，换一档会重新载入页面）、操作说明；手机上多一项油门（自动 / 手动）

地址栏参数，方便截图和录屏固定机位：

| 参数 | 作用 |
|---|---|
| `view=front` / `side` / `rear` / `wheel` / `top` | 起始机位 |
| `still=1` | 关闭转台自动旋转 |
| `paint=lava` / `acid` / `midnight` / `glacier` / `volt` / `toxic` / `sunset` / `chroma` / `silver` / `stealth` | 这一次临时换个车漆（不记到车上） |
| `car=gt` / `rs` / `lm` / `st` / `xr` / `brute` / `ronin` / `nomad` | 起始车型（不写就用上次在车库里选的） |
| `theme=chalk` / `heat` / `candy` / `acid` / `volt` | 这一次临时换个特效配色（不写就用这台车自己的） |
| `ui=0` | 隐藏界面（包括菜单），只留画面 |
| `mode=drive` | 跳过主菜单，直接进入自由驾驶 |
| `mode=race` | 跳过主菜单，直接开一场比赛 |
| `laps=2`、`rivals=5`、`level=easy` / `normal` / `hard` | `mode=race` 时的圈数、对手数量、难度 |
| `cam=far` / `near` / `hood` / `cockpit` | 开车时的起始机位 |
| `map=city` / `mountain` | 选赛道：城市的霓虹湾、山里的云岭（不写就用上次在菜单里选的） |
| `map=test` | 自由驾驶进入阶段 2 的灰盒测试场（测试场不能比赛） |
| `time=day` / `dusk` / `night` | 起始时段（不写的话城市是夜晚，山路是黄昏） |
| `weather=clear` / `rain` / `fog` / `snow` | 起始天气（不写的话城市下雨，山路是晴天） |
| `q=high` / `medium` / `low` | 画质档位（不写的话电脑是高、手机是低；在设置里改过就用改过的） |
| `touch=1` / `0` | 强制按触屏设备 / 按电脑来布局（在电脑上调手机界面时用 `touch=1`，再把窗口缩成手机大小） |
| `px=3.7` | 渲染分辨率上限，单位百万像素。默认 3.7（相当于 2560×1440）；`px=0` 不限制，按屏幕原生分辨率渲染，截图时用 |
| `fx=-ssr,-ao,-mb,-dof,-lens,-msaa` | 关掉对应的后期效果（反射、环境光遮蔽、运动模糊、景深、镜头效果、多重采样），对比和排查用 |

### 线上版本

- <https://umbra.dsxzai.com/>（自定义域名）
- <https://umbra-gt.pages.dev/>（Cloudflare Pages 的原始地址，内容相同）

需要支持 WebGPU 的浏览器。第一次打开要下载约 33 MB 的车辆模型（下过一次就存在本机了，以后不用再下）。

重新发布：`npm run deploy`（先构建，再用 `wrangler pages deploy` 把 `dist` 传到 Pages 项目 `umbra-gt`；要先 `npx wrangler login` 登录过）。两个地址会一起更新。主菜单最下面有车辆模型的素材署名，公开发布时不要去掉。

自定义域名是怎么绑的：域名上站着一个只有几行的转发 Worker（`cloudflare/domain-proxy.js`，配置在 `wrangler.worker.jsonc`，名字 `umbra-gt-domain`），把请求原样转给 Pages。没有直接用 Pages 的自定义域名功能，是因为那要在域名解析里加一条 CNAME，而命令行的登录凭证没有改解析的权限；Workers 绑自定义域名时 Cloudflare 会自动建好解析和证书。这个 Worker 不用跟着游戏重新发布；想换域名就改 `wrangler.worker.jsonc` 里的 `routes` 再 `npx wrangler deploy -c wrangler.worker.jsonc`。以后如果在 Cloudflare 控制台里给 `umbra` 加了指向 `umbra-gt.pages.dev` 的 CNAME 并在 Pages 项目里绑上域名，就可以把这个 Worker 删掉。

## 在手机上玩

0.11.0 起可以装到手机主屏幕上当应用玩（PWA）。电脑上的画面和操作没有变。

**安装**：用手机浏览器打开 <https://umbra.dsxzai.com/>，

- iPhone / iPad：Safari 底部的分享按钮 →「添加到主屏幕」；
- 安卓：Chrome 右上角菜单 →「添加到主屏幕」或「安装应用」。

从主屏幕的图标打开是全屏的，没有地址栏。第一次要联网把车的模型下完（约 33 MB），之后断网也能打开、能开车。

**横屏**：游戏只有横屏一种样子。

- 装成应用后，应用清单里写了横屏，安卓会直接横着打开；
- 手机竖着拿的时候（包括 iPhone——它不认清单里的横屏），整个画面会自己转九十度铺满屏幕，把手机横过来拿就是正的，不用去开系统的「自动旋转」；
- 做法（`src/core/viewport.ts`）：页面里所有东西都放在 `#app` 这一层里，竖屏时把这一层按「宽 = 屏幕的高、高 = 屏幕的宽」摆好再旋转九十度；画布大小、手指的位置都按这一层的坐标算（`appSize()`、`toApp()`）。屏幕矮（不到 560）时给页面加上 `compact`，菜单和比赛界面按小屏幕排。

**触屏操作**（`src/ui/touch.ts`）：

| 位置 | 按钮 |
|---|---|
| 左下 | 左、右两个方向键 |
| 右下 | 刹车（停稳后继续按住是倒车）、漂移（带着方向按一下就甩起来）、氮气 |
| 右上 | 暂停、换镜头、复位 |

- **自动油门**（默认）：碰过任意一个键以后车就自己给油，不用一直按着——两个拇指要留给方向、漂移和氮气。按住刹车时不给油。想自己控制油门，在设置里把「油门」改成手动，右下角会多一个油门键。
- 自由驾驶时换时段、换天气、开自动驾驶（电脑上是 L、K、P 三个键）：点暂停，暂停菜单里有这三项。
- 车库里拖动画面转着看车；赛前的特写镜头点一下屏幕跳过。
- 开车时屏幕不会自己熄灭；在安卓的浏览器里直接玩（没装到主屏幕）时，点「开始比赛」或「自由驾驶」会进全屏并锁成横屏；iPhone 的浏览器不支持网页进全屏，装到主屏幕以后本来就是全屏。

**画质档位**（`src/core/quality.ts`）：手机默认是「低」，在设置里可以换；换一档要重新载入页面（阴影、雨雪的数量是建场景时定的）。

| 档位 | 渲染分辨率上限 | 关掉的后期 | 阴影 | 雨雪数量 |
|---|---|---|---|---|
| 高（电脑默认） | 2560×1440 | 无 | 2048，三级，到 320 米 | 全量 |
| 中 | 180 万像素 | 屏幕空间反射 | 1536，三级，到 260 米 | 七成 |
| 低（手机默认） | 100 万像素 | 屏幕空间反射、环境光遮蔽、多重采样 | 1024，两级，到 180 米 | 一半 |

**离线缓存**（`public/sw.js`、`public/manifest.webmanifest`、`public/_headers`）：

- 程序本身（页面、脚本、样式、图标）按版本号存一份：页面注册缓存脚本时地址后面带着版本号（`sw.js?v=0.11.0`），发了新版、版本号一变，浏览器就装上新的，旧的那一份随后清掉。所以**每次发布都要改 `package.json` 里的版本号**，不然装在手机上的还是旧版。
- 车的模型单独存一份（`umbra-models-1`），不跟着版本号清——每发一版都让手机重下三十多兆不合适。**重新导出过 `public/models/` 里的 glb，就把 `sw.js` 里的 `MODELS` 加一**。
- 打开页面先走网络（一联网就能拿到新版），断网了才用存着的；其余文件先看存着的。
- 只有正式版（`npm run build` 出来的）才注册缓存脚本，开发时（`npm run dev`）不注册，免得改了代码看到的还是旧的。

**怎么检查**：`npm run build` 之后 `npm run pwa-check`。脚本起一个无头 Chrome（手机横屏的大小、带触屏），自己把 `dist` 托管在本机，查应用清单、图标、缓存脚本有没有装上、东西有没有存下来；然后把托管的服务关掉（真的断网），重新打开页面，看游戏还能不能进到开车。`GAME_URL=https://umbra.dsxzai.com/ npm run pwa-check` 查线上的。

**没验证过的**：以上都是在电脑上用手机大小的窗口和无头浏览器测的，没有在真手机上跑过。手机上的帧率、发热、内存够不够（两张地图加四台车的模型不小）、触屏按钮的大小和位置顺不顺手，都要真机试了才知道。需要 WebGPU：iOS 26 以上的 Safari、安卓上新版的 Chrome。

手柄可以按 Start 暂停，但暂停菜单里要用键盘或鼠标操作。

漂移是过弯的主要手段（0.9.1 重做，0.9.2 把收车改得又快又干脆）：同一个街角，漂着过比老老实实刹车过快两三秒，弯里的车速高一倍多。

- **发起**：带着方向拉手刹——立刻开始漂，不用等车身先滑出角度；或者带着方向点一脚刹车。
- **拐多快和车速无关**：车身甩出的角度越大，行进路线每秒往弯里拐得越多（打满方向约每秒 70°–85°）。以前是按固定的横向力算的，车速翻一倍、拐弯就慢一半，高速时漂了等于没漂。只有车速很高时受横向加速度上限（3.2 g）限制，拐得慢一些。
- **高速入弯会明显掉速**：横着滑的减速度按车速的平方涨，两百进弯头一秒能掉四五十；掉到一百出头就基本不掉了，踩着油门可以一直漂下去。所以是「越慢拐得越紧」。
- **方向盘管角度**：往弯里带着方向保持大角度（打满约 49°、弧线最紧；只打一半角度小一些、弧线宽一些），拉住手刹角度最大（约 58°、掉速也最快，过回头弯用）。想一直漂下去就一直带着方向，键盘连点也行。
- **收车**（0.9.2）：松开方向、往反方向带一下（不用打到底）、踩刹车、或者松油超过三分之一秒，都是收车。约 0.4 秒内漂移结束，车走直：
  - 收的时候行进方向和车头各让一半——行进方向往车头那边再拐一点（大约是当时侧滑角的一半多），车头也往回摆一点。所以要在车头略微转过出弯方向的时候松手。
  - 收车期间不再接着往弯里拐，松手就是「别再转了」。
  - 只反打不会甩到另一边去：反打就是收车，按住不放也只是正常地往那边拐。想连着往反方向漂（S 弯），反打的同时再拉一把手刹。
- **油门**：漂移中踩着油门有一股沿车头方向的推力（约 0.6 g，车速超过 110 千米/时逐渐减弱、到 165 没有）。给油 = 往车头指的方向冲。

参考数字（原型车，`npm run corner-test`，赛道 588 米处的直角弯，中心线半径 19 米）：

| 入弯车速 | 不漂移（自动驾驶，提前刹车） | 漂移 |
|---|---|---|
| 120 千米/时 | 8.86 秒，弯里最低 52 | 不刹车、点一下手刹：6.79 秒，弯里最低 112，不蹭墙 |
| 160 千米/时 | 8.54 秒，弯里最低 52 | 不刹车、点一下手刹：5.90 秒，弯里最低 126，不蹭墙（九个入弯点里只有一个能过；拉住手刹 0.8 秒更稳，6.06 秒） |
| 200 千米/时 | 8.37 秒，弯里最低 52 | 先刹到 160 再漂：5.63 秒；不刹车直接漂会撞墙 |

重做之前同样「不刹车、点一下手刹」，九个入弯点没有一个能过去，全是重重撞在外侧墙上——所以感觉漂移对过弯没用。

收车的数字（`npm run sim` 里「收车」一节，110 千米/时、侧滑 48° 时开始收）：

| 怎么收 | 0.9.1 | 0.9.2 |
|---|---|---|
| 松开方向 | 0.85 秒才结束，车头自己又转 19°，行进方向一共再拐约 66° | 0.41 秒，行进方向再拐约 28°，车头回摆 12° |
| 反打一下 | 1.00 秒 | 0.39 秒 |
| 轻轻反打一半 | 留着十几度的角度一直漂，停不下来 | 0.40 秒 |
| 踩刹车 | 0.91 秒 | 0.44 秒 |

对手不会漂移，过弯还是提前刹车的开法；难度没有按新的漂移重新校准，会漂的话现在比「困难」的对手快不少。

漂移和腾空会给氮气回充。

### 自动驾驶

自由驾驶时按 `P`，车自己沿赛道跑，再按一次交还给你。0.9.3 起它是**表演式**的开法（`src/drive/ShowPilot.ts`），为的是录出来好看：

- **直道**：油门到底；前面够长、氮气够多就开氮气，一直喷到快到下一个弯的刹车点。上拱桥之前不开（飞得太远，落地离下一个弯太近）。
- **急弯**（半径小于六十米，城市赛道一圈八个）：进弯前往外侧靠，车速太高就先点一脚刹车，到入弯点带着方向拉手刹把车甩起来，然后往弯里带着方向给油漂过去。每一步都估一下「现在松手的话车最后会朝哪走」，估出来已经对准弯后的路了就松手收车。
- **缓弯**（湖滨的大半圆）：不漂，贴着抓地极限跑。
- **连续弯**：上一个弯出来正好在下一个弯的内侧，没有空间把弯拉开，会慢一点进、晚一点甩。
- **撞停了**：倒一小段、把车头摆回赛道方向再走。
- 入弯车速和松手的时机按车调过：重的车入弯慢一点，又重又长的皮卡早一点松手；雪地上入弯更慢、刹车更早。

|---|---|---|---|---|
| RONIN | 59.3 秒 | 64.7 秒 | 8 次，共 10 秒 | 9.5 秒 |
| RS | 60.2 | 66.2 | 8 次，共 11 秒 | 10.2 秒 |
| ST | 61.4 | 67.7 | 8 次，共 11 秒 | 11.1 秒 |
| UMBRA GT | 61.5 | 67.4 | 8 次，共 11 秒 | 10.7 秒 |
| LM | 61.7 | 67.6 | 8 次，共 12 秒 | 10.6 秒 |
| XR | 61.9 | 67.8 | 8 次，共 11 秒 | 9.5 秒 |
| BRUTE | 64.2 | 70.3 | 8 次，共 13 秒 | 10.7 秒 |
| NOMAD | 64.9 | 69.9 | 8 次，共 13 秒 | 9.6 秒 |

每圈都没有卡住、没有重的碰撞；唯一一次记到的轻碰是拱桥落地那一下（冲击 0.2–0.4，老老实实开也有）。比老的抓地跑法（GT 一圈 80–83 秒）快二十秒左右。在游戏里雨夜的 GT、雪夜的 RONIN 各跑过一整圈，结果和无头仿真一致。

**在山路上**（0.10.0）开法不一样，因为弯不一样：

- **发卡弯**（转一百七八十度，半径三十米）：从外侧进，贴近弯口才甩，然后一直漂到出弯。这套手感下漂起来以后弧线拐多急基本只看车速，稳定下来是 110–120 千米/时、半径三十米出头，正好是发卡弯的半径（弯就是照着它定的）。漂的时候方向不是打到底，而是盯着前面的路按需要的深浅带着；车速掉下来、弧线收紧了，就补一脚氮气把车速撑住——所以快到发卡弯的时候会留四成氮气。
- **大半径的回头弯和长弯**（半径 80–96 米）：没法从头漂到尾（高速漂移掉速很快，车速一掉弧线就收紧）。开法是「甩进去」：不刹车，带着 190–200 千米/时拉手刹横着进弯，一秒多钟里掉到 140，快贴到内侧时收车，剩下的半个弯抓地走完。又重又长的两台车（BRUTE、NOMAD）收车慢，这种弯不甩，抓地过。
- **山脊上的坡顶**：前面不开氮气，车速压到 205 以下。

八款车各跑三圈（`node scripts/show-lap.ts 3 <车型> map=mountain`，雪地加 `grip=0.8`）：

| 车型 | 一圈（干地） | 一圈（雪地） | 漂移 | 氮气 |
|---|---|---|---|---|
| RONIN | 92.3 秒 | 101.1 秒 | 4 次，共 8 秒 | 14.5 秒 |
| RS | 94.3 | 103.9 | 4 次，共 8 秒 | 14.1 秒 |
| ST | 94.5 | 104.9 | 4 次，共 8 秒 | 16.1 秒 |
| XR | 94.8 | 105.2 | 4 次，共 8 秒 | 13.3 秒 |
| LM | 95.0 | 104.9 | 4 次，共 8 秒 | 14.2 秒 |
| UMBRA GT | 95.0 | 104.5 | 4 次，共 8 秒 | 14.2 秒 |
| BRUTE | 97.7 | 108.5 | 2 次，共 6 秒 | 13.1 秒 |
| NOMAD | 98.6 | 108.5 | 2 次，共 7 秒 | 14.1 秒 |

没有卡住，没有重的碰撞；轻蹭护栏的有：干地 RS、LM 各一次，NOMAD 两次（冲击最重 0.35），雪地 NOMAD 一次。比不漂移的基准（GT 103.4 秒）快八秒多——山路上弯大，漂移能抢的时间没有城里那么多，主要是直道上的氮气。

**电影镜头**（0.13.0，`src/drive/CineCamera.ts`）：打开自动驾驶，镜头就自动换成像转播和电影那样在一组机位之间切来切去，上下收进两条黑边，开车的界面藏起来。按 `V`（手机上点「镜头」）回到平时的机位，再按一圈又回来。

| 机位 | 怎么拍 |
|---|---|
| 路边 | 镜头立在前面几十米的路肩上不动，长焦盯着车，车冲过来、掠过去 |
| 摄像塔 | 同上，但立在护栏外面七八米高的地方（只在山路上有：城里路边是楼） |
| 摇臂 | 架在前面路的上方九米多，车从底下过 |
| 航拍 | 在车的斜后上方二十多米跟着飞，看得见路的走向 |
| 车头前 | 架在车前面的路上倒着走，拍车头冲着镜头来 |
| 侧面跟拍 | 贴着车的一侧走，慢慢往后滑 |
| 贴地追尾 | 比平时的追尾低得多、广得多 |
| 环绕 | 绕着车转半圈 |
| 轮边 | 绑在车身侧后方贴着地，漂移的时候烟从镜头前面冒 |
| 追尾 | 平时开车的那个机位，隔一阵用一下 |

- **怎么挑**：按权重随机，不连着用同一种。车一甩起来，就从贴着车走的机位切到看得清车身角度的（车头前、航拍、轮边、路边）；隧道、棚洞、高架下面不用高处的机位；车很慢的时候不用定点机位。
- **镜头之间是硬切**（电影和转播都是这样），一个镜头之内的移动和变焦是平滑的。长焦镜头带景深，背景是虚的。
- **不会钻进墙里**：贴着车走的机位被收在路的范围以内，不低于地面；定点机位每隔零点一秒用物理世界查一次视线，被山或楼挡住了就换。

**比赛里的自动驾驶**（0.13.0，`src/race/RacePilot.ts`）：比赛中按 `P`（或者在暂停菜单里点）也能开。开车的还是上面这个表演式的自动驾驶，另外加了三样：

- 等发车信号；
- 看着点别的车——前面有车挡着，从对方偏着的另一侧换线过去；贴得太近还在往上追，就按前车的车速收油，这时不开氮气；并排的时候往外让半个车身。漂起来以后不管别的车（甩到一半没法改主意），所以弯里偶尔会碰到；
- 倒车也脱不了困、翻了、开出赛道了，和对手一样放回赛道中间。

无头仿真里让它扮演玩家（`node scripts/race-sim.ts hard 7 2 show`，山路加 `map=mountain`，雪地加 `grip=0.8`）：四种情况都从最后一位发车、第一个冲线，没有被放回赛道过。

| | 两圈用时 | 最快圈 | 漂移 | 碰撞（最重） |
|---|---|---|---|---|
| 城市，困难，7 个对手 | 2:10.2 | 61.5 秒 | 17 次 | 12 次（1.00，第一个街角人堆里） |
| 山路，困难，7 个对手 | 3:16.3 | 94.9 秒 | 10 次 | 2 次（1.00，第一个发卡弯出弯蹭了外侧护栏） |
| 城市雪地，普通，5 个对手 | 2:19.7 | 67.4 秒 | 16 次 | 4 次（0.54） |
| 山路雪地，普通，5 个对手 | 3:34.4 | 104.5 秒 | 12 次 | 1 次（0.18） |

它比「困难」的对手每圈快十几二十秒（对手不会漂移），所以看它比赛基本是第一圈一路超上去、然后领跑。

老的那个提前刹车、不漂移的自动驾驶（`src/drive/Autopilot.ts`）留着：无头仿真里验证赛道、量基准圈速（`npm run city-lap`）和对手的 AI 用的还是它。

**追尾机位跟着车型变**（0.13.0，`src/drive/ChaseCamera.ts`）：两个追尾机位原来是照着又矮又窄的原型车定的，换成掀背车、皮卡这种又高又方的车，路的尽头正好被车挡死（皮卡在近追尾下几乎占满画面）。现在镜头按每台车的车高（含高尾翼、皮卡的防滚架）抬高、按车长后退：抬到「视线擦着车顶过去，落在车前十五米（近追尾是二十二米）的路面上」为止，原型车几乎没变，皮卡的远追尾从 1.55 米抬到 3.1 米。

驾驶室视角下方向盘会跟着转，仪表屏显示实时的车速、挡位、转速和氮气；漂移时视线会自动转向行进方向。能看到驾驶员握着方向盘的双手（十点和两点的位置，跟着方向盘转，转角大了方向盘在手里滑过去）；车内有一盏补光，画面整体曝光也比车外视角高一点，不再是下半截一片黑。

## 城市赛道"霓虹湾"

一座 7 × 8 路网的临河城市，中间一条河，一侧是带公园和摩天轮的半岛。赛道一圈 2613 米、9 个弯，逆时针：

1. 起点在高架铁路下面的大道上，全油门直线
2. 冲上红色钢桁架拱桥过河，桥顶会腾空
3. 对岸金融区的高楼峡谷，左转进入下层街道（上面盖着另一层路面，白天也亮着灯）
4. 再左转，从平桥过河回来
5. 右转上河岸，接湖滨大道：绕半岛的 180° 左手长弯，半径 165 米，外侧是湖
6. 老城区连续四个直角弯（右、左、左、右）
7. 左转回到高架下的发车直道

赛道沿线的岔路口都用红白护栏封住，车只能沿赛道跑；护栏外面的街区只作为街景。八个直角弯的路口另有一套指引（见下面「弯道的指引」）。

整座城市是程序生成的，所有数据在 `src/city/cityLayout.ts`：路网尺寸、河和湖岸的位置、桥、高架、下层街道、赛道路线、护栏、每栋楼的位置和高度。渲染和物理碰撞共用这一份数据，改了布局两边同时生效。

```bash
npm run city-check
```

输出赛道长度、每个弯的位置和半径、护栏和楼的数量。后面跟一个图片路径（`node scripts/city-check.ts 俯视图.png`，需要装 ImageMagick）还会画一张俯视图。

```bash
npm run city-lap
```

不开浏览器，让自动驾驶在完整的城市碰撞体里跑两圈，报告圈速、最高车速、偏离中心线的最大距离和所有碰撞。改完布局或手感先跑这个，确认赛道还能跑通。

### 弯道的指引（0.14.0）

城里八个直角弯原来长得一模一样：一条街开到头，正前方一道红白护栏，左右两边看上去完全对称——另一侧封死的那道护栏退在岔路里面二十多米，被街角的楼挡着，要开进路口才看得到。隔着一条街看不出是往左还是往右。0.14.0 给每个弯加了四样东西：

| | 在哪 | 是什么 |
|---|---|---|
| 箭头屏 | 正对着来车的那道护栏上 | 一排 LED 屏，24 米宽、近 3 米高，八个「>」指着出弯的方向，一道亮光一格一格地朝那边追过去 |
| 大箭头 | 箭头屏上方，离地 5–8 米 | 一块 9 米宽的屏，整块是一个箭头。隔着一两个街区、或者前面有一群车挡着的时候，先看到的是它 |
| 红叉屏 | 不该拐过去的那一侧 | 一排红色的叉。这道护栏从岔路里面挪到了楼的外墙线上，来车在街角就能看到那边是封死的 |
| 地面箭头 | 入弯前两排（离路口中心 21 米和 44 米） | 每条车道一个刷在路面上的转向箭头 |

- **哪个路口往哪边拐**不是手写的：`cityLayout.ts` 的 `buildTurnHints` 沿赛道走一遍，记下每个路口从哪条臂进来、从哪条臂出去，护栏的分工（`Barrier.kind`：`side` 直道两边的岔路、`ahead` 正对来车、`wrong` 不该拐的那一侧）、箭头屏的方向、地面箭头都从它取数。以后改了路线，这些跟着变。
- **屏**是一个材质画的三种图案（`materials.ts` 的 `createLedBoardMaterial`）：黑板子上十厘米一颗灯珠，离远了灯珠比一个像素还小就按平均亮度画。白天也亮着；雾天更亮一些，不然透不出来。屏在夜里往地上洒一片琥珀色（或红色）的光，烤在地面光照图里。
- **地面箭头**是路面着色器里画的，不是贴上去的片，所以和车道线一样会磨损、被雨打湿、被雪盖住。哪个路口的哪条臂上画、往哪边指，查一张「一个路口一个像素」的小图（`src/city/turnMap.ts`）。箭头的贴图只在箭头自己那几块里才真的取样，别处的路面不为它多花时间。
- **两道护栏现在都贴着楼的外墙线**，路口读起来就是一个直角弯。原来正前方那道退在岔路里十三米，等于留了一块冲过头以后的缓冲区，现在没有了：刹车晚了会直接撞上箭头屏。碰撞体跟着屏一样高。直道经过的路口没动。
- **橱窗里的倒影**：和箭头屏垂直的玻璃会把它映出来，镜子里的箭头左右是反的，正好指着错的方向。两处都处理了：箭头屏不再凹在岔路里（两侧楼的橱窗照不到它）；通向弯道的那条街——入弯前的一整个街区——两边的立面不做屏幕空间反射，只留环境贴图里的反光（`turnMap.ts` 的 `facesTurnApproach`；`surface.ts` 里反射率给 -1 表示这个像素不反射）。湿路面上的倒影是上下翻的，方向不变，照常有。
- **自动核对**：`npm run city-check` 会把每个弯的指引方向和赛道实际拐的方向对一遍，并确认正前方和另一侧各有一道护栏、都在楼的外墙线上。
- **无头仿真的成绩一点没变**：自动驾驶 GT 一圈还是 61.48 秒，比赛（困难、7 个对手）两种开法的用时、碰撞次数和 0.13.0 一模一样——自动驾驶和对手本来就不会开到那几块缓冲区里去。

**没做的 / 知道的毛病**：第二个弯在下层街道的出口，头顶那层路面挡着，开到跟前才看得到大箭头（下面那排箭头屏和地面箭头看得到）；过桥进第三个弯时大箭头被桥的桁架挡掉一部分；通向弯道的那几条街两边的玻璃没有了实时倒影（别的车、霓虹灯在这些橱窗里也照不出来了）；雪天地面箭头被雪盖着；湖滨大道的长弯没加（路本身是弯的，看得出来）。

## 山路赛道「云岭」

0.10.0 加的第二条赛道。和城里那条正相反：没有直角弯，全是顺着山势的弧线，有七十米的落差。

路是照着《极品飞车》里山路的感觉定的（热力追踪的山区之字路、不羁城外的山道、卡本峡谷）：**路宽**——双向四车道，和城里的路一样宽，漂得开、超得了车；**弯大而流畅**——十二个弯里只有两个发卡弯是急的，其余都是半径七十五米到一百六十米的大弧线，带着速度过；**弯道往里倾斜**（横坡最多三度半）；再加上隧道、高架桥、一个会飞起来的坡顶、弯道外侧一排排导向牌、路边的大广告牌和远处的雪山。能查到的公开资料里对这几代的道路设计讲得很少（只有地名和评测里的概括），这些要点是按对游戏本身的了解定的。

不漂移的基准自动驾驶一圈 103.4 秒（GT），零碰撞。「困难」难度的七个对手加一个 AI 扮演的玩家跑两圈：全部完赛，最快圈 104–106 秒，零碰撞、没有被放回赛道的。会漂移的表演式自动驾驶见「操作」里的「自动驾驶」。

**怎么做出来的**（都在 `src/mountain/`，全部程序生成，没有用 Blender）：

- **线路**（`mountainLayout.ts`）：和城市一样是「折点 + 每个折点的转弯半径」，相邻折点之间是直线、折点处抹成圆弧；西南角的长弯是一段直接指定圆心的圆弧。连成一圈以后做两遍滑动平均，直线和弯的交接处就成了渐变的（进弯是慢慢打方向，不是一下打满）。
- **高低**：先定了山的大形状——朝南的一面山坡，南边是湖边的谷底（22 米），往北爬到 92 米的台地，带一点大起伏。路的高度就取它脚下山坡的高度，再把太陡的地方抹平（最陡 8%）。所以路是贴着山走的，不是架在半空或者埋在地下。
- **山体**：离路远的地方是山本来的样子；靠近路的地方往路基上接——比路高的一侧挖成石壁（陡），比路低的一侧填成路堤（缓）。隧道所在的那道石梁、桥下的那条山沟是在山坡上额外加的，路不跟着它们走。隧道和桥在哪也是算出来的：石梁高出路面十米以上的那一段是隧道，山沟低于路面四米半以上的那一段是桥。
- **山体的网格**分两层，落在同一个高度函数上：贴着路的六圈（护栏外到 38 米，四米一排，路堑路堤的形状靠它），和铺满 1.6 千米见方的十米大格子。路附近的格点往下压了几米，藏在前一层下面；隧道口附近的大格子不画（十米一格太粗，会有一个斜面插进洞里）。再外面是一圈 75 米一格的远山，一直铺到三千米外，四百多米以上终年积雪。
- **碰撞**（`mountainPhysics.ts`）：路面和路肩是一圈三角网格（带横坡），两侧护栏是一段段盒子（画面上半人高，碰撞体四米高，车翻不出去），护栏外三十几米的地面也有碰撞。两张地图的碰撞体在同一个物理世界里、位置是重叠的，各归一组，同一时间只开着当前这张的（`PhysicsWorld.beginGroup` / `setGroupEnabled`）。
- **路边的东西**（`MountainWorld.ts`）：波形护栏和橙色反光柱头、桥上的混凝土防撞墙、弯道外侧的黄黑导向牌（箭头指向弯里，被车灯照到会亮）、六块大广告牌（都是虚构的牌子）、起终点的龙门架、四千六百多棵针叶树（路边四十几米以内的是细的那一版、会投影子，再远的是简化版）、路边的石头、湖。
- **路灯**只在发车直道、两个发卡弯、两个大回头弯的外侧、桥上和隧道口有。其余路段夜里只有车灯和月光，所以山路上车灯比城里亮得多，路面的边线和中线上每十二米有一颗反光道钉。
- **昼夜和天气**用的是城市那一套（`atmosphere.ts`、`weather.ts`、地面光照图），参数按山里另定：白天太阳在东南，照着朝南的山坡；黄昏太阳压在湖的西南角；夜里没有城市的光，天是深蓝的、星星多。雨、雪、闪电抽成了两张地图共用的 `src/city/Precipitation.ts`。不指定时段和天气的话，山路是黄昏、晴天。

### 沿线的景物（0.12.0）

0.11 之前这条路只有路、护栏、清一色的锥形树和几块广告牌，开一圈下来没有一处记得住。0.12.0 对着《极品飞车》的实机画面重做了一遍沿线：

- 看的是《热力追踪》重制版的海崖郡（Bear Hollow 一带的林间山路）、《宿敌》的红景郡、《不羁》和《热度》城外的路。记下来的差距是：那边的树有**高高的光树干**、轮廓参差，针叶和阔叶混着长；山坡是**土石底色上一片片林子**，不是匀匀的一片绿；路边有**成块的黄褐色层状岩壁**、干草和土路肩；几乎每一帧里都有**电线杆和电线**、警告牌、头顶的绿色路牌；一路上有加油站、餐馆、隧道口的红白导向板这类**一眼认得出的地方**。
- 做的时候守一条线：**所有新东西都立在护栏外面，不加碰撞体**。车开不到的地方不需要碰撞，无头仿真的圈速也就一秒不变（表演式自动驾驶 GT 一圈还是 95.0 秒）。

**植被**（`src/mountain/flora.ts`）：

- 树不再是圆锥搭的，改成「面片」：几片竖着交叉的四边形，贴一张带透明轮廓的树。贴图不是图片文件，是启动时在画布上画的——针叶树一层层往下垂的枝、阔叶树一根主干不断分杈再在枝梢上点一团团叶子。八种：两种云杉、光着半截树干的松树、半枯的老冷杉，绿、金黄、锈红三种阔叶树，白桦。
- 按海拔分带：湖边和谷底是**秋天的阔叶林**（金黄、锈红里夹着没黄的绿和白桦），山腰是**针叶林**，山脊上树矮而稀。林子按噪声分成一片一片，中间留草地；坡下的一侧和发车直道朝湖的一侧故意种得稀，看得见山谷和湖。
- 一棵树只有十几个顶点，所以数量从四千多棵加到七千六百棵（手机上的低画质档是三千九百棵），三角形反而少了九成。面片侧对镜头时会淡掉（另外几片这时候正对着），法线统一朝上再往树冠外侧偏，看不出是十字插片。树冠顶上随风轻轻晃。
- 地面上：护栏外一条稀稀拉拉的干草，再往外是草丛、蕨、野花、红叶和绿叶的灌木、小树苗、枯枝，一万多丛（低画质档五千多丛）。
- 谷底的阔叶林里空中飘着落叶（`Leaves.ts`，做法和雪花一样，在着色器里算，围着镜头循环），开快了从镜头两边掠过去。只在海拔低的地方有，雨雪天没有。

**山体和石头**（`mountainMaterials.ts`、`MountainWorld.buildRocks`）：

- 远山原来是一团光滑的白：网格七十五米一格，雪线又低。现在在着色器里按噪声把法线搅一搅，山坡上有了沟和梁；雪只在缓的地方挂得住，陡的石壁露着；远处的山坡按「一团团树冠、中间露着草地」的颜色画。
- 石头改成黄褐色的层状砂岩（参考图里路边那种），缝里发暗。草地在高处和朝阳处是干的、金黄色，谷底的林子下面铺着落叶的颜色。
- 路堑一侧（山坡被切开的地方）嵌着一排有棱有角的大岩块，连成石壁；别处零星散着小的。

城市有白天、黄昏、夜晚三个时段，自由驾驶中按 `L` 切换，过渡约 2.6 秒。每个时段是一组参数（`src/city/atmosphere.ts` 里的 `TIMES`）：主光方向和颜色、天光、天空、雾、城市灯光开多少、曝光、泛光、调色。改时段的观感只动这张表。

**天空**：一个着色器覆盖三个时段，渐变、日盘或月盘、光晕、霞光、云、星星都由参数驱动。

**城市灯光**：

- 全城三千多盏灯（路灯、高架下的灯管、下层街道的顶灯、桥上的灯、招牌、橱窗、摩天轮）在加载时烤成一张俯视的"地面光照图"，路面、人行道、墙面、护栏在着色器里按坐标查这张图。所以夜里每盏路灯下都有光斑，但没有几千个实时光源。
- 窗户按楼分配亮灯比例，幕墙写字楼整层亮，住宅零星亮；底层店面有内景；招牌和灯具自发光。
- 车头大灯的光束、车底的软阴影、尾灯洒在地上的红光，都是地面材质里按车的位置直接算的（`src/city/cityLights.ts`）。

**车身反射**：试驾时车用一个跟着它走的实时反射探针（`src/drive/CarProbe.ts`），每帧重拍立方体贴图的两个面。车漆和玻璃上映出来的是身边真实的街道，霓虹和路灯会从车身上滑过。另外从全城的灯里挑最近的几盏，放上真正的点光源，只照车身，提供流动的高光。

**后期管线**（`src/core/Engine.ts`），按顺序：

1. 主画面一次渲染同时输出颜色、法线、反射参数、每个像素的运动速度
2. 环境光遮蔽（GTAO，半分辨率）
3. 屏幕空间反射（SSR，半分辨率）：水面、玻璃幕墙、车窗，以及路面上一层淡淡的反光
4. 运动模糊（按速度缓冲）：车跟着镜头走所以是清楚的，路和楼在糊
5. 景深（只在车库）：对焦在车上，背景虚化
6. 泛光、暗角
7. 色调映射（ACES），然后在显示空间里调色：分离色调、饱和度、对比度
8. FXAA 抗锯齿，最后是轻微的边缘色散和胶片颗粒

车库和试驾用两套配置，进出时切换。

**性能**：后期按像素算钱，所以渲染分辨率默认封顶在 2560×1440。在 M3 Max 上夜景全开、自动驾驶跑完几乎一整圈（76 秒），每秒都是 60 帧；2880×1620 下前半圈 36 秒也稳定 60 帧。要量帧率请让浏览器窗口保持在前台（后台窗口的动画会被浏览器降速），开车时按 `T` 看右上角的数字。

## 天气与湿地面

城市有晴、雨、雾、雪四种天气，自由驾驶中按 `K` 切换，和时段可以任意组合（一共十二种）。默认是雨夜。

天气不是一下子切过去的，各个量有自己的快慢（`src/city/weather.ts`）：

- 雨大约两秒下起来、两秒停
- 地面下雨后约六秒湿透；雨停后慢慢变干，约二十五秒干透。所以雨停之后有一段"雨后"的状态：天晴了，地还是湿的
- 雾约五秒起来
- 雾天地面是潮的，但没有积水
- 雪说下就下，积雪约十二秒铺满；雪停后约二十秒化完

**下雨时**

- **天空**：云盖满整片天，太阳、月亮、星星都被遮住；白天阴雨天也会亮起招牌和橱窗。
- **雨丝**：一万根，分布在跟着镜头走的一个盒子里。方向是雨相对镜头的运动方向，停着时竖直落下，开快了迎面扑来。会被路灯、霓虹和车头大灯照亮。下层街道和高架正下方淋不到雨。
- **湿地面**：沥青变深、反光变强；低洼处和路缘边积出水洼，水洼接近镜面，映出霓虹、楼和车；雨点在水面上打出一圈圈涟漪。人行道同样会湿。有顶的地方（下层街道）路面保持干燥。
- **轮胎水雾**：车轮把水卷起来甩到车后，车速越快越多；会被灯光照亮，贴近车尾的部分被尾灯染红。
- **镜头水滴**：画面上挂着的小水珠和往下滑的大水珠，每一颗都折射它后面的画面。开快了会被风吹掉一部分。
- **闪电**：下雨时每隔几秒到十几秒打一次，两连闪。前方天上出现一道带分叉的闪电，同时整个场景被照亮一瞬间。

**起雾时**：能见度降到两百米左右，天空融进雾里，泛光更强；夜里的雾会被城市的灯光映亮。

这些特效（雨丝、水雾、闪电）不在主场景里，而是放在引擎的"特效叠加层"里单独渲染再叠上去，原因见 `src/core/fx.ts`。

天气特效几乎不占性能：同一段路上晴、雨、雾三种天气每帧的渲染耗时基本一样（M3 Max、2560×1440 下都在 11 毫秒上下）。

**下雪时**

- **雪花**：九千片，跟着镜头走。车停着时是慢慢飘下来的小白点，开快了每一片都被拉成迎面扑来的一道。会被路灯和车灯照亮。
- **积雪**：路面上的雪不是均匀的一层——车轮压过的两道是发黑的雪水，露出湿沥青，边缘弯弯曲曲；车道中间是压实的脏雪；靠路缘的地方最厚最白。人行道中间有一条踩出来的道。屋顶、雨棚、树冠、停着的车、护栏顶上都盖着雪。高架下面和下层街道没有雪。
- **天色**：满天云，空气发白；夜里满城的灯被雪和低云来回反射，天是暖的橙粉色，背光处也被地上的雪映亮。
- **车辙**：车轮压过的地方会留下车辙（`src/city/SnowTracks.ts`）——雪被压实、露出发暗的湿路面，里面是一格格人字形的胎纹印，两边各挤出一道雪棱。你的车四个轮子都留，对手的车留后轮的两条；一共保留最近的九千节（约三公里），雪化了车辙跟着消失。高架下面没有雪，也就没有车辙。
- **雪粉**：车轮卷起来的是一团团白色的雪粉，比雨天的水雾浓一些。和轮胎水雾一样，只在露天、真有雪（有水）的路段才有。
- **抓地力**：积雪铺满时所有车的轮胎抓地下降两成（过弯、刹车、起步都受影响），对手和自动驾驶也跟着早刹车、慢过弯。无头仿真里同样水平的一场比赛，圈速慢约 9 秒。

雨和雾只改画面，不改抓地力：湿地面和干地面开起来手感一样。只有雪天会变滑。

- 四套车身在启动时一次全部加载好（`Car.load`），换车是瞬间的事。车漆、轮毂、卡钳、车灯、仪表这些选项对四台车都有效；「尾翼」开关只对原型车的几款有效。

## 特效

全部由 `src/fx/CarFx.ts` 根据车辆的物理状态触发，不需要额外按键。

**画风是写实的**（0.9.0 重做）：只做真车上会有的东西。0.8.0 那套「彩色烟团加发光线条」里的地面光痕、气流线、冲击波、彩色火星都去掉了；0.7 的尾灯拖光加了回来。

| 特效 | 什么时候出现 |
|---|---|
| 轮胎烟 | 轮胎横着滑（漂移）或者起步烧胎时，从轮胎接地的地方冒出来，贴着地往后卷、再慢慢升起来散开。是几十上百片没有轮廓的软片叠成的一股，不是一团一团的；有受光面和背光面（太阳、月亮），被路灯从上面照亮，刹车时车尾那一截被尾灯染红。轮胎要滑上半秒烧热了烟才浓，蹭一下只有淡淡一点。路面湿了或者有雪时不冒烟 |
| 尾灯拖光 | **只在加速时**：猛加速（约 0.3 g 以上）和开氮气时，尾灯在身后拉出长长的红光（长曝光照片里的光轨）；匀速巡航、刹车、松油时没有。拖出来的形状就是这台车尾灯的形状，见下面「尾灯拖光的形状」。白天淡一些 |
| 氮气 | 点燃的一瞬间排气口一闪、喷出一团火星；然后是带亮芯的长焰；画面四周是一道道从中间往外飞的流光 |
| 落地 | 四个轮子压出一圈尘土；落得重还有底盘蹭出的火花 |
| 碰撞 | 撞上的位置一下闪光，细长的火花沿着被蹭的面飞溅，画面同时抖一下色散 |
| 胎痕 | 轮胎打滑时在路面上留下橡胶印，四个轮子各一条，最多保留最近的 1600 节。湿路面留不下胎痕 |
| 排气回火 | 高转速升挡的瞬间，或者高转速突然松油门时，排气口喷一小团橙色的火和几粒火星 |
| 刹车盘发红 | 高速重刹时刹车盘慢慢烧红，松开刹车后慢慢冷下来 |
| 雪地车辙 | 见「天气与湿地面」 |

**配色**：车库面板最下面的「特效」可以换五套（霜白、烈焰、霓虹粉、酸性绿、电光紫），定义在 `src/fx/themes.ts`，跟着车走。换的是轮胎烟的颜色和氮气喷焰的颜色；第一套是真车的样子（白烟、蓝焰），其余几套相当于换了彩烟胎。尾灯拖光永远是红的。

**尾灯拖光的形状**（0.9.3，`src/fx/tailLamps.ts`、`src/fx/TailTrails.ts`）：每台车的尾灯记成几盏「灯」（位置、宽、高、亮度、是不是圆环），每盏灯沿着车走过的路拖一道自己形状的光——扁的灯拖一片横着的光，有高度的灯再加一片竖着的，圆环灯拖出两边亮、中间暗的空心光管。

| 车 | 尾灯 | 拖出来的样子 |
|---|---|---|
| UMBRA GT 和它的四个款式 | 贯穿式的括号形灯带 | 中间一整片薄薄的光幕，两头各一段更亮的光带，最外侧各一道往下拐的竖条。各款式车尾宽窄不同，位置跟着换算 |
| BRUTE | 两边各三根竖条 | 六道并排的光 |
| RONIN | 两边各两个圆环，中间一条细灯带 | 四根空心的光管，中间一片很淡的光 |
| NOMAD | 尾门两侧立式的灯，位置高 | 两道竖着的光刃 |

**速度感**（`DriveMode.applyLook`、`ChaseCamera`、`Engine`，0.9.0 再加强）：

- **氮气的镜头**：点燃后车从镜头前面加速窜出去——拉远是一根弹簧带着走的，从慢到快再放缓，大约 0.7 秒拉开 3.7 米（略微冲过头再回到 3.4 米），同时压低、视野拉宽约 18°；松开氮气后慢慢收回来。0.9.0 是一瞬间跳到远处，0.9.1 改成了这样有过渡的。拉丝变长也是渐进的。
- **车速和加速**：车速越高镜头越远、越低、视野越广；猛加速时镜头被甩在后面，重刹时往前贴，幅度比以前大一半。
- **过弯倾斜**：镜头往弯里歪，弯越急、越快歪得越多（最多六度左右），漂移时按车身甩出去的角度再加一点。驾驶室视角里只歪三分之一。
- **运动模糊**：快门从 1/125 秒放慢到 1/28 秒（0.8 是 1/160 → 1/45），画面四周往外的径向拉丝加长七成，最长能到画面宽度的六分之一。拉丝长了以后等距取样会出一格一格的重影，所以每个像素把取样位置随机错开（`Engine` 里自己写的那段）。
- 边缘色散和暗角跟着加重；亮的灯在画面上拉出横向的光条。

烟、拖光、火花、喷焰画在引擎的特效叠加层里（和雨丝、水雾同一层）；胎痕和雪地车辙贴在路面上，所以在主场景里。烟的质感来自启动时算出来的一张可平铺的云雾噪声图（`src/fx/smoke.ts`），没有外部图片。

## 比赛

从主菜单"开始比赛"进入。可选 1 / 2 / 3 / 5 圈，1 / 3 / 5 / 7 个对手，简单 / 普通 / 困难三档难度，以及时段和天气；设置会记住。

**流程**

1. 所有车摆上发车格（两列交错），你排最后一位。
2. **赛前镜头**（约 12 秒，按空格、回车或 Esc 跳过；「重新开始」时不再放）：
   - 贴着路面、从发车线前面慢慢横移的全景，打出赛事标题和这一场的圈数、车数、时段、天气；
   - 两个对手的特写（排头的那辆从车头斜前方，另一辆从车尾斜后方），带发车位、名字和车型的名牌；
   - 你自己的车：车头斜前方的低机位（轰一脚油门）、前轮特写（前轮往里打一把）、车尾特写（再轰一脚，松油门时排气管回火）；
   - 镜头绕着你的车从斜前方转到车尾，交还给追尾镜头。
3. 倒数 3、2、1。这时车被刹住动不了，但可以轰油门。
4. "GO!" 之后起步。赛道上每隔三百多米有一道检查点的光门（一圈 7 道，加上终点线），只显示你下一道要过的和再下一道。
5. 跑完规定圈数冲线。冲线后车交给 AI 慢慢开，两三秒后弹出结算；对手陆续冲线时结算表会跟着更新。
6. 结算页可以"再来一局"或回主菜单。比赛中按 Esc 暂停，可以继续、重新开始、调音量或退出。

赛前镜头的做法（`src/race/RaceIntro.ts` 管机位、字幕和轰油门的时机，`src/ui/raceIntroUi.ts` 管黑边和字）：镜头之间直接硬切，每切一次响一声并抖一下色散；画面换成带景深的一套（背景虚化，`Engine` 的 `cinema` 配置），上下加电影黑边，开车的界面先藏起来。参考的是《极品飞车》的做法：开赛前快切几个场上车辆的镜头，再甩回玩家的车尾、倒计时出现。地址栏加 `intro=0` 可以关掉。

0.9.0 为了让这一段撑得起画面，改了几处：

- **打光**：像拍汽车广告那样围着被拍的车打两盏灯——暖白的主光在镜头一侧的斜上方，偏冷的轮廓光在车的后方，给车顶和车肩勾一道亮边（城市的材质不吃这两盏灯，只照得到车）。原来是一盏架在镜头上的灯，像开了闪光灯，车身是平的。
- **车漆**：镜头贴得近、灯又是直射的时候，一个像素正好是一粒金属颗粒那么大，画面上是一片噪点；这一段把颗粒压到两成多（`paintFlakeGain`）。
- **雨丝和雪花**：改到景深之后再叠。景深是按主画面的深度算的，雨丝没有深度，以前会被当成背后那面墙一起虚化，糊成一块块白斑。
- **机位**：换成长焦、压低、慢而匀速的推移，背景压成一片光斑；全景不再从高处往下拍（那样拍到的是平的路面和店面的顶）。多了一个车头斜前方的镜头。
- **调色**：反差和饱和度各提百分之六七，暗角加重，夜里的横向光条多一点，边缘色散收掉。

**规则**

- 名次按"沿赛道跑了多远"排。进度只认沿着赛道走的距离：离开赛道太远进度就停住（界面提示"偏离赛道"），回到赛道才继续算，所以抄近道不会多算。
- 逆着赛道开超过一秒多，界面提示"逆行"。
- 比赛中按 R 会把车放回赛道中间、车头朝前、从静止起步，代价就是损失的时间。翻车或掉出地图时自动这样处理。

**比赛界面**：左上是名次、圈数和实时排行榜，右上是总用时、本圈用时和最快圈，对手头顶有名次和名字的名牌。

左下是**实时小地图**（`src/ui/miniMap.ts`，0.9.0 重画）：一块半透明的灰底上只画赛道路线，不画街区和别的路。它是从车的后上方斜着往前看的，带透视——路线是一条有宽度的带子，近宽远窄，前面两三百米的弯往哪拐、有多急一眼看得出来（开得越快看得越远）。前方五百米要走的一段是亮的，赛道的其余部分是淡的；自己是黄色的箭头（漂移时会斜过来），对手是带颜色的点（跑出范围的贴在边上），下一道检查点是路线上的一个黄圈。地图右侧有一块**转弯提示**：下一个弯往哪边、是直角弯、回头弯还是缓弯、还有多少米；进到 90 米以内变黄，到弯口变成粉色的「转弯」。

**对手**（`src/race/RivalAI.ts`）：和自动驾驶同一套底子（盯着前方一点打方向，按前面弯道的急缓倒推车速），再加上：

- 各走各的线，不都挤在路中间。
- 前面的线上有车就换一条空的线超过去；两边都没地方就跟着，不往上撞。
- 三档难度差在过弯敢用的抓地、刹车点、直道极速和会不会用氮气。发车位靠前的对手更快。
- 橡皮筋：领先你太多的对手会放慢一点，落后太多的会追一点，幅度按难度不同（`src/race/roster.ts`）。
- 卡住超过两秒半、翻车、掉出赛道的对手会被放回赛道中间。

对手的车和你的车是同一个模型、不同车漆。为了同屏八辆车不掉帧，对手的车把一百多块网格按材质合并成了 9 块，没有内饰和卡钳（`src/race/RivalCar.ts`）。

比赛逻辑（`src/race/` 里除了 `RivalCar`、`RaceMarkers`、`RaceSession` 以外的部分）不依赖画面，可以不开浏览器跑完整场：

```bash
npm run race-sim
```

参数依次是难度、对手数量、圈数、"玩家"的水平（玩家也由 AI 扮演，`slow` / `mid` / `fast` / `none`），例如 `node scripts/race-sim.ts hard 7 3 fast`。会输出每个人的圈速、名次变化、碰撞次数和被放回赛道的次数。改了 AI、赛道或车辆手感之后先跑它，确认所有人都能跑完。

各难度下对手的圈速（无头仿真）：简单约 95–98 秒，普通约 85–90 秒，困难约 80–82 秒。作为对比，不漂移的基准自动驾驶一圈约 80–83 秒，会漂移的表演式自动驾驶约 59–65 秒。难度只和 AI 扮演的"玩家"比过，没有按真人的水平校准过。

**性能**：M3 Max、2880×1620、雨夜、7 个对手同场，实测每帧耗时的中位数 16.7 毫秒（60 帧），95% 的帧在 18.7 毫秒以内。

## 声音

没有用任何录音素材，所有声音都是用浏览器的 Web Audio 现场合成的（`src/audio/GameAudio.ts`）。浏览器要求先有一次点击或按键才能出声，所以进入主菜单后点任何一个按钮声音才会开始。

| 声音 | 怎么来的 |
|---|---|
| 引擎 | 按 V8 的点火规律合成的波形，音调跟转速走；油门越大越亮、越响，松油门会闷下去；顶到红线会断油；换挡时顿一下 |
| 对手的引擎 | 每辆一路，有远近、左右声像，擦身而过时有音调变化 |
| 轮胎 | 干地打滑是尖叫声，湿地是压水的沙沙声 |
| 路噪、风噪 | 跟着车速变大 |
| 雨声、雷声 | 雨声跟着雨量；闪电之后隔一小会儿打雷 |
| 氮气 | 开启时一股喷气声，引擎音调略微拔高 |
| 碰撞、落地、回火 | 跟着阶段 6 的特效一起触发，越重越响 |
| 提示音 | 倒数、出发、过检查点、完成一圈、最快圈、最后一圈、冲线、名次升降、菜单的点击 |

驾驶室视角下，外面的声音（风、雨、轮胎、对手）会闷一些。暂停时驾驶的声音收掉，菜单的提示音还在。主音量在"设置"里调，按 M 静音；音量会记住。

没有做背景音乐。

## 性能

**怎么量**：`npm run perf`（先另开一个终端 `npm run dev`）。脚本起一个无头 Chrome 打开游戏，在赛道上三个固定位置各量一次"不等屏幕刷新、连续出帧"的平均每帧耗时（CPU + GPU），画面固定 2560×1440。16.7 毫秒以下才稳得住 60 帧。

- `node scripts/perf.ts "fx=-ssr"`：带上地址栏参数再量（可以给多组）。
- `node scripts/perf.ts --parts`：逐项关掉场景里的东西和后期效果，看各占多少。可以加 `--time=day --weather=clear --spot=40` 换场景，`--only=阴影` 只量一项。

不要在普通浏览器窗口里量：页面不在前台时浏览器会给它降速，数字会越量越大。机器上别的程序也在用显卡时，同一个配置两次能差出几毫秒；`--parts` 是"开、关交替量再取中位数"，受的影响小，绝对数字多量两遍取稳定的那次。

**现状**（M3 Max，2560×1440）：

| | 画面重制后、优化前 | 优化后 |
|---|---|---|
| 夜晚下雨 | 约 18–21 毫秒 | 约 10.7–11.7 毫秒 |
| 夜晚晴天 | 约 17.6–20 毫秒 | 约 10.5–11.3 毫秒 |
| 白天晴天 | 约 15–18 毫秒 | 约 10.8–11.8 毫秒 |

0.9.0（新的烟、更长的运动模糊、雪地车辙、车尾多出来的零件）之后重量了一遍：夜雨 10.3、夜晴 10.5、白天 11.8 毫秒，和上表在同一个范围。要注意这个脚本量的是车停在三个固定位置时的画面，量不到「漂移时满屏是烟」「开着氮气拉丝最长」这两种最吃力的情况。

**山路**（0.10.0）：和城里放在同一轮里量，山路每帧比城里少两三成（那一轮机器上别的程序占着显卡，两边的绝对数字都偏大、不能和上表比，只能互相比）。山上没有上千栋楼的立面和满街的灯，贵的是树（四千多棵，近处的是网格、远处的是面片）和三公里外的远山。

量的时候要注意两件事：对着构建好的版本量（`npm run build` 后 `npx vite preview`，再 `GAME_URL=http://localhost:4173/ npm run perf`），不要对着开发服务——量到一半改了源码，页面会自己重新载入，这一轮就废了；别的浏览器窗口里开着游戏也会抢显卡。

0.12.0 沿线重做以后重新量了一遍（这次机器是空闲的，数字可信；对着构建好的版本，同一轮里量）：山路夜雨 8.0、夜晴 7.9、白天 7.7 毫秒，城市夜雨 9.5、夜晴 9.4、白天 9.8 毫秒；重做之前的山路（线上的 0.11.0）是 7.9 / 7.9 / 7.5，基本没变——树从网格换成面片省下来的，正好抵掉新加的景物。山路的低画质档是 3.0–5.0 毫秒。

0.14.0 给城里的弯加了箭头屏和地面箭头，和线上的 0.13.0 交替量了三轮城市（这一轮机器上别的程序在占显卡，绝对数字偏大，只能互相比）：0.13.0 三轮的平均是 12.5 / 13.2 / 16.0 毫秒，0.14.0 是 12.2 / 14.1 / 15.6 毫秒，互有高低，没有量得出来的差别。

**手机**用的是低画质档（见「在手机上玩」），在电脑上相当于 `q=low`；真机上的帧率没有量过。

**做了哪些优化**：

- **分块裁剪**（`src/city/chunks.ts`）：全城同一种材质的东西原来合并成一整块网格，每画一遍（主画面、三级阴影、探针的每个面）都要把全城一百万个三角形过一遍。现在顶点多的网格按 275 米的格子切开，树和停着的车按格子分组，镜头外的整块跳过。
- **反射探针**：不再拍杂物、防火梯、树、停着的车（`src/core/layers.ts`）；拍照时不重画阴影（原来每拍一个面，三级阴影都跟着重画一遍）；逐级缩小图每拍完一轮才生成一次。从 4 毫秒降到 0.5 毫秒。
- **夜里不算主光的阴影**：月光很暗，街上的光来自路灯的光照图。昼夜交替的一瞬间所有材质要重新编译，会卡一下。
- **路面**：着色器里现算的十五次噪声改成查一张可平铺的噪声贴图。
- **后期**：环境光遮蔽每像素采样从 12 次减到 8 次；白天的干路面不参与屏幕空间反射。
- **车**：内饰不投影。

**还剩什么**（夜晚下雨，单位毫秒）：屏幕空间反射约 3.1、环境光遮蔽 1.6、运动模糊 1.6、多重采样 1.6、楼体立面 1.0、探针 0.5。耗时主要跟像素数走：把渲染分辨率降到 100 万像素（`?px=1`）能再省约 5 毫秒。

## 调校手感

车辆参数全部集中在 `src/drive/VehicleConfig.ts`。物理代码不依赖渲染，可以不开浏览器直接跑数据：

## 整车模型的节点约定

后续阶段（物理、特效）都按这套命名取节点：

```
Car                     整车根节点，车头朝 +Z，左侧为 +X，轮胎接地面 y = 0
├─ Body                 车身（侧倾、俯仰加在这里）
│   ├─ BodyWing         扰流翼（可隐藏）
│   ├─ BodyTailBand / BodyTailLightBar / BodyTailBadge  车尾饰板、贯穿式灯带、发光字标
│   ├─ BodyDiffuser / BodyRainLight / BodyExhaust       扩散器、雨灯、排气尾喉
│   ├─ SteeringPivot    方向盘转轴（运行时创建）
│   ├─ FX_Exhaust_L/R   排气口（尾焰、回火）
│   ├─ FX_Headlight_L/R 大灯
│   └─ FX_Taillight_L/R 尾灯
└─ Wheel_FL/FR/RL/RR    转向轴心（绕 Y 轴，正值向左）
    ├─ Wheel_xx_Spin    滚动轴心（绕 X 轴，正值向前），带轮胎、轮辋、刹车盘
    └─ Wheel_xx_Caliper 卡钳（不随车轮滚动）
```

轴距 2.80 米，前轮距 1.95 米，后轮距 1.96 米，轮胎半径 0.384 米（以上是原型车 `car.glb` 的数）。

另外三台车（`brute.glb`、`ronin.glb`、`nomad.glb`）用同一套命名，所以游戏里不用区别对待。它们多两个空节点，标出镜头的机位：`Cam_Cockpit`（驾驶员的眼睛）和 `Cam_Hood`（车头机位）；原型车没有这两个节点，用代码里写死的位置。车身是一整块 `BodyShell`（按材质分成车漆、玻璃、车灯几部分），内衬是 `InteriorLining`。

重新生成这三台车：在打开了 `assets-src/car.blend` 的 Blender 里依次执行 `assets-src/build_cars.py` 和 `assets-src/cars_def.py`，然后调用 `build_brute()` / `build_ronin()` / `build_nomad()`，再用 `export_car('brute', 'brute.glb')` 导出到 `public/models/`。`assets-src/cars-extra.blend` 是生成之后另存的一份工程。

材质按名字分组：`Paint_Primary`、`Paint_Secondary`、`Paint_Accent`（后加部件用的副色，不带 AO 贴图）、`Glass`、`Light_Head`、`Light_Tail`、`Light_TailBar`、`Light_TailBadge`、`Light_Signal`、`Dashboard`、`Rim_Dark`、`Rim_Bright`、`Caliper`、`BrakeDisc`、`Tire_Side`、`Tire_Tread`、`Trim_Black`、`Exhaust_Tip`、`LicensePlate` 等。
